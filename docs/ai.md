# AI 활용: 가정을 데이터로 바꾸고, 결과를 근거와 함께 설명한다

AI는 계산을 대신하지 않는다. 계산은 지금처럼 규칙 기반 모델이 하고, AI는 두 곳에서 쓴다.

| 기능 | 하는 일 | 모델·방법 | 안전장치 |
|---|---|---|---|
| 1. 버스 계수 학습 | 근거 없이 둔 "세대당 첨두 버스 이용객 0.3명"을 실제 승하차 데이터로 추정 | 입주 전후 비교 + 대조군 보정(이중차분), 원점 회귀 | 2026-10-27부터 추정치(0.032명)가 기본값. 예전 가정과 비교하려면 가정값 슬라이더를 0.3으로 옮김 |
| 2. AI 정책 리포트 | 화면 수치를 번호 붙은 사실(F1, F2…)로 묶어 Claude가 3~5문장 리포트를 씀 | Claude Haiku 5.5, 구조화 출력 | 문장마다 근거 번호 필수. 근거에 없는 숫자를 쓴 문장은 서버가 걸러 냄(`ai-worker/src/numbers.ts`) |
| 3. 말로 시나리오 만들기 | "우미린 입주를 2029년으로 미루면?" → 화면 조작 목록 | Claude Haiku 5.5, 구조화 출력 | 실제 단지 id·값 범위로 검사(`ai-worker/src/whatif.ts`), 적용 전에 바뀌는 내용을 보여 주고 확인을 받음. 결과 수치는 AI가 아니라 모델이 계산 |

## 1. 버스 계수 학습 (`scripts/fit_bus_rate.py`)

- 데이터: 경기데이터드림 [경기도 정류소 별 승하차 인원 집계](https://data.gg.go.kr/portal/data/service/selectServicePage.do?infId=MZCREO5CKHZM6PJEA55P37391662&infSeq=1)(정류소·일자별 승하차, 2020~). 파일(zip)을 `data/raw/boarding/`에 넣고 실행한다.
- 방법
  1. 단지 반경 400m 정류소들의 평일 하루 승차 합계를 월별로 구한다.
  2. 입주 전 6개월 평균 vs 입주 2~7개월 뒤 평균(입주 지정 기간 약 2개월을 건너뜀).
  3. 같은 시기 입주 단지 반경 800m 밖 오산시 정류소(대조군)의 변화율로 "입주가 없었다면"의 값을 만든다.
  4. 증가분 ÷ 세대수 = 세대당 하루 승차. 여러 단지는 원점 회귀로 묶는다.
  5. 모델 계수(첨두 1시간 이용객) = 세대당 하루 승차 × 첨두 비중. **이 데이터에는 시간대가 없어 첨두 비중(기본 15%)은 가정**이다. `python3 scripts/fit_bus_rate.py 0.2`처럼 바꿔 볼 수 있다.
- 검증: 정답을 아는 합성 데이터(파라곤 주변 정류소에만 하루 534회 증가 → 세대당 0.5)를 넣어 0.5가 그대로 나오는 것을 확인했다.
### 결과(2026-10-27 실행, 데이터 2023-01 ~ 2026-08, 44개월)

| 단지 | 입주 | 세대 | 비교 구간 | 반경 400m 정류소 | 평일 하루 승차(전 → 후) | 대조군 보정 기대값 | 증가 | 세대당 하루 승차 |
|---|---|---|---|---|---|---|---|---|
| 호반써밋 라센트 | 2024-03 | 897 | +6~+11개월 | 3 | 3.4 → 197.9 | 4.6 | +193.3 | 0.216 |
| 오산 세교파라곤 | 2026-04 | 1,068 | +2~+7개월 (입주 초기, 묶음 제외) | 6 | 355.7 → 628.3 | 373.7 | +254.5 | 0.238 |
| 세교 중흥S-클래스 에듀파크 | 2024-10 | 1,245 | +6~+11개월 | 6 | 76.4 → 356.9 | 108.4 | +248.4 | 0.2 |
| 한신더휴 | 2025-03 | 844 | +6~+11개월 | 5 | 44.7 → 217.8 | 48.3 | +169.5 | 0.201 |
| 모아미래도 | 2025-04 | 414 | +6~+11개월 | 8 | 680.6 → 873.8 | 695.2 | +178.6 | 0.431 |

- **묶은 추정: 세대당 하루 버스 승차 0.216회**(반경 400m). 반경 민감도: 400m 0.216 · 600m 0.295 · 800m 0.489.
- 첨두 비중 15%(가정)를 곱하면 **세대당 첨두 이용객 0.032명**. 모델 기본값 0.3명은 반경·첨두 비중을 넉넉히 잡아도(800m, 25%) 약 0.12명을 넘기 어려워 **3~10배 과대**일 가능성이 크다.
- 해석: 신도시 가구는 자가용·철도(오산역) 이용이 많아 버스 승차가 생각보다 적다.
- **기본값으로 채택(2026-10-27)**: 이 값을 쓰면 새 단지가 더하는 버스 수요는 노선 수송력에 비해 작다. 단, 이 계수는 "세대당 승차"이지 "노선의 남은 자리"가 아니다. 그날 저녁 기존 이용객(아래)을 넣기 전까지 노선 이용률 11%는 빈 버스를 가정한 값이었다. 예전 결론과 비교하려면 가정값 패널에서 "세대당 첨두 버스 이용객" 슬라이더를 0.3으로 옮기면 된다. 바뀐 발표 수치는 `docs/demo-numbers.md`.
- 남은 가정: 첨두 1시간 비중 15%. 첨두 비중을 25%로, 반경을 800m로 넉넉히 잡아도 세대당 약 0.12명이다.

### 기존 버스 이용객 추정(`scripts/estimate_bus_background.py`, 2026-10-27 저녁 추가)
- 심사 대비 점검에서 "기존 이용객 0"이면 버스 여유 결론이 성립하지 않는다는 지적이 나와 추가했다.
- 같은 승하차 데이터의 마지막 3개월(2026-06~08) 평일 정류소 승차를, 그 정류소를 지나는 노선에 첨두 운행 횟수 비율로 나눠 노선별로 더한다(조사 범위 정류소 351곳 중 데이터가 있는 303곳, 노선 72개). 첨두 비중 15%를 곱해 양방향 첨두 1시간 승차를 만든다.
- 모델은 여기에 **최대 재차 비율(가정 0.5)**을 곱해 노선의 기존 부하로 쓴다. 승하차 데이터에 노선 정보가 없고 노선별 정류소 순서(GBIS `getBusRouteStationListv2`)도 아직 받지 못해 구간별 재차 인원을 계산하지 못했기 때문이다. 키가 있으면 `scripts/fetch_route_stations.py`로 받을 수 있다.
- 결과(2027): 100%를 넘는 노선 0개, 가장 붐비는 8번 96%(기존 승차만으로). 재차 비율 0.3 → 58%, 0.6 → 116%(1개 초과), 0.7 → 135%(6개 초과). 결론은 "**신규 수요는 작지만 주요 노선은 이미 붐빈다, 증편 여부는 재차 조사로 확인할 과제**"이고 "버스는 여유"가 아니다.
- 이중 계산 방지: 2026-08까지 입주한 단지 주민은 기존 승차에 들어 있으므로, 새 수요는 그 뒤 입주 단지만 더한다(입주율 곡선만큼).

### 같은 데이터로 추정한 것 두 가지(2026-10-27 밤 추가)
- **입주율 곡선**(`scripts/fit_movein_ramp.py`): 입주 뒤 정류소 승차가 늘어나는 모양으로 "입주 시작 뒤 몇 달에 걸쳐 들어오는가"를 추정. 37% → 65% → 89% → 100%.
- 도보권 반경은 계수 추정과 같은 **400m**로 모델도 통일했다(예전 600m).
- 데이터 처리에서 확인한 것: 원본은 zip → 월별 tar → 일자별 csv.gz(CP949)이고, 2025년 5월만 열 이름이 영문(RIDE_DATE 등)이다. 단지와 함께 새로 생긴 정류소는 생기기 전 승차를 0으로 본다. 승차는 입주 뒤 12개월 가까이 계속 늘어 비교 구간을 입주 6~11개월 뒤로 잡았다.
- 한계: 정류소 승차에는 단지 밖 주민도 섞인다(대조군 보정으로 공통 변화만 뺌). 단지 표본이 적다. 하루 단위라 첨두 비중은 따로 가정해야 한다.

## 2·3. AI 중계 서버 (`ai-worker/`)

정적 사이트(GitHub Pages)에는 API 키를 둘 수 없어, Cloudflare Worker가 대신 Claude를 부른다.

- 주소: `/api/report`, `/api/whatif`(POST), `/api/health`(GET)
- 허용 출처: `wrangler.jsonc`의 `ALLOWED_ORIGINS`(배포 사이트와 로컬 확인 주소만)
- 사용량 제한: 접속 주소별 하루 30회, 전체 하루 500회(`DAILY_LIMIT_*`)
- Claude 호출은 미국 동부에 고정한 Durable Object에서 보낸다(가까운 지역이 홍콩 등일 때 Anthropic이 403으로 거부하는 문제 회피)
- 테스트: `cd ai-worker && npm test`(숫자 검사·조작 검사 7개), `npm run check`(타입 검사)

### 배포 상태
- Worker: https://seokyo-twin-ai.iungjae48.workers.dev (`/api/health`로 확인), 모델 claude-haiku-5-5
- 실제 호출 확인: 리포트 약 4초(문장 5개, 걸러진 문장 0), What-if 약 3.7초(복합 질문 → 조작 2개)

### 배포 방법
```bash
cd ai-worker
npm install
npx wrangler login                        # 브라우저에서 Cloudflare 로그인
npx wrangler secret put ANTHROPIC_API_KEY # 키 입력(화면에 남지 않음)
npm run deploy                            # 출력되는 https://seokyo-twin-ai.<계정>.workers.dev 주소를 확인
```
그다음 `index.html`의 `<meta name="seokyo-ai" content="">`에 그 주소를 넣고 사이트를 다시 배포한다.
로컬에서는 `http://localhost:8765/?ai=<Worker 주소>`로 시험할 수 있다(로컬에서만 허용).
